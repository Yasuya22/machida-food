# アカウント準備の手順（MACHIDA FOOD 開発用）

- 作成日：2026年11月3日
- アカウントの作成・契約は、ご本人が行ってください（CLAUDE.mdのルール）
- 画面の文言やボタンの位置は、各サービスの更新で変わることがあります。迷ったら各サービスの公式ヘルプを確認してください

---

## いま作るもの・あとで作るもの

| サービス | 役割 | 作る時期 | 費用 |
|---|---|---|---|
| **GitHub** | プログラムの保存と変更履歴 | **いま** | 無料 |
| **Supabase** | データベース・ログイン・画像の保存 | **いま** | 開発中は無料プランで十分 |
| Vercel | アプリの公開（ホスティング） | 公開の準備をするとき | 無料のHobbyプランは商用利用不可。実店舗で公開するときはProプラン（月20ドル） |
| ドメイン | `machida-food.jp` のようなアドレス | 公開の準備をするとき | 年1,500〜3,000円程度 |

**最初に共通で準備すること**
- 事業用のメールアドレス（YSY総合サービス用）でそろえて登録すると、後の管理が楽になります
- パスワードは使い回さず、パスワード管理アプリでの保管をおすすめします
- どのサービスも**2段階認証を必ず設定**してください（会員の個人情報を扱うため）

---

## 1. GitHub

1. GitHub の公式サイトで、事業用のメールアドレスでアカウントを作成（無料プランのままで大丈夫です）
2. 2段階認証を設定
3. 新しいリポジトリを作成
   - 名前の例：`machida-food`
   - 公開範囲は **Private（非公開）**
4. 作成できたら、リポジトリの名前を教えてください。今回作った設計ファイル一式（CLAUDE.md、PROJECT_BRIEF.md、データベース設計とテスト）を最初の中身として入れる手順をご案内します

---

## 2. Supabase

1. Supabase の公式サイトで、**GitHubのアカウントでログイン**してアカウントを作成（管理がまとまります）
2. 2段階認証を設定
3. 新しいプロジェクトを作成
   - 名前の例：`machida-food-dev`（開発用）。本番用は公開前に別で作ります
   - **リージョンは Tokyo（東京）** を選ぶ（町田の利用者に一番近く、表示が速くなります）
   - データベースのパスワードは強いものを設定し、パスワード管理アプリに保存
   - プランは Free
4. 作成できたら教えてください。今回のデータベース設計を入れる手順をご案内します

**大事な注意**
- Supabaseの設定画面には「API キー」が表示されます。このうち **`service_role`（サービスロール）のキーは、会員データをすべて操作できる鍵**です。チャットやメール、画面の共有などで**誰にも送らないでください**（私にも送る必要はありません）
- 無料プランは、1週間ほど使わないとプロジェクトが一時停止します。開発中は問題ありませんが、実店舗で公開するときは有料プラン（月25ドル程度）に切り替えます

---

## 3. Vercel（公開の準備をするときでOK）

1. Vercel の公式サイトで、GitHubのアカウントでログインして作成
2. 公開するときにご相談のうえ、Proプランへの切り替えと、GitHubのリポジトリとの接続を行います
3. 外部への公開は、CLAUDE.mdのルールどおり、承認をいただいてから行います

---

## 作り終えたら

GitHub と Supabase ができた段階で、次の2つを教えてください。

- GitHub のリポジトリ名（例：`ysy-sogo/machida-food`）
- Supabase のプロジェクトを作成できたかどうか（キーやパスワードは送らないでください）

その後、
1. 設計ファイル一式をGitHubに保存
2. データベース設計をSupabaseの開発用プロジェクトに反映
3. Next.js でアプリ本体（Phase 1）の作成開始

の順に進めます。
