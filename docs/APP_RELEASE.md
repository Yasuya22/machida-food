## 2. 段階B・C：本番環境とPWA公開

1. 本番用 Supabase プロジェクトを**東京リージョン**で作成（運営者）→ `supabase/migrations/` を順に適用（`supabase/dev/` と `supabase/tests/` は本番では実行しない）
2. Supabase の Pro プラン（月25米ドル程度。無料プランは1週間使わないと停止するため本番には不向き）
3. メール送信サービス（SMTP。Resend・SendGrid 等）を契約し Supabase に設定（開発用の送信はチームのアドレスにしか届かない）
4. Supabase Auth の Site URL・Redirect URL を本番ドメインに設定
5. ホスティングに GitHub を接続、環境変数（`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`）を設定して公開
6. 公開時に `next.config.ts` の `X-Robots-Tag: noindex` と `layout.tsx` の `robots` を見直す
7. 確認：iPhone（Safari）・Android（Chrome）で「ホーム画面に追加」→ 全画面で起動、オフライン画面、会員証QR、店舗のカメラ読み取り（HTTPSが必要）

## 3. 段階D：Google Play（TWA）

PWA をそのまま Android アプリとして包む方式（Trusted Web Activity）。中身は Web 版と同じなので、更新は Web を直すだけで反映される。

1. Google Play Console で開発者登録（初回25米ドル、本人確認）
2. Bubblewrap（Google 公式ツール）で Android アプリを作成：`store/android/twa-manifest.example.json` の値（公開URL・アプリ名・色）を使う
3. 署名鍵の指紋（SHA-256）を `public/.well-known/assetlinks.json` に入れて公開（アプリと公開URLが同じ持ち主であることの証明。これがないとアドレスバーが表示される）
4. 非公開テスト（個人アカウントは12人以上・14日間）→ 本番申請
5. ストア掲載情報（`docs/STORE_LISTING.md`）、プライバシーポリシーURL、データセーフティ（取得するデータの申告）、コンテンツのレーティング（お酒に関わる表現あり）を入力
6. **アカウント削除**：アプリ内の退会（マイページ → 退会する）に加え、Web上の削除方法のURL提出が必要

## 4. 段階E：App Store

Apple は「Webサイトを包んだだけのアプリ」を審査で断ることが多い（審査ガイドライン 4.2）。そのため Capacitor で包み、**アプリならではの機能**を加えて申請する。

- 候補：店舗用のネイティブQR読み取り、来店・特典のプッシュ通知（Phase 2 のお知らせ機能と合わせる）、会員証の明るさ自動調整、オフライン時の会員情報の表示
- 必須：アプリ内退会（対応済み）、プライバシーポリシーURL、App プライバシー（取得データの申告）、年齢区分（お酒に関わる表現）
- ログイン方法に**LINE などの外部ログインを追加する場合は「Sign in with Apple」等の追加が必要**（ガイドライン 4.8）。メールのみの現状は対象外
- ビルドには最新の Xcode が必要。**お手元の MacBook Air（Intel）で最新の Xcode が動くかは要確認**。動かない場合はクラウドのビルドサービス（GitHub Actions の macOS 環境など）を使う
- 手順：Apple Developer Program 登録 → App Store Connect でアプリ作成 → TestFlight で社内確認 → 審査提出
